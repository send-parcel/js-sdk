# SendParcel JS SDK

Клієнт App API v2 SendParcel на TypeScript; у пакет іде зібраний JavaScript з типами. Архітектура й контракт —
[docs/architecture.md](docs/architecture.md): прочитати перед будь-якою правкою.

## Жорсткі правила

- **Без залежностей під час виконання.** `dependencies` у `package.json` порожні. Нова залежність
  — лише рішенням людини в розмові.
- **Без фреймворків і середовища.** Ні Vue, React, DOM, `window`, `document`, `localStorage`, ні
  Node-модулів (`fs`, `http`). Лише `fetch`, `URL`, `URLSearchParams`, `Headers`,
  `AbortController`.
- **Лише API v2.** Логіка сайту (сесія, вхід через форму, переклади, формат дат кабінету) живе у
  споживачі, не в SDK.
- **Падати гучно.** Відповідь не `2xx` — `ApiError`, обрив — `NetworkError`, неочікуване тіло —
  `ResponseFormatError`. Тихого `catch`, значень «за замовчуванням» замість помилки й `?.` на місці,
  де `undefined` означає биті дані, немає.
- **Секрети не логуються й не зберігаються** поза об'єктом, який передав споживач.
- **Ресурс додається, коли його потребує споживач.** Поля й коди помилок беруться з документації
  API v2, а не вигадуються.

## Код

- TypeScript у `src/` (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`), ES-модулі,
  `"type": "module"`. Імпорти — з розширенням `.js` (`./http/url.js`): так їх розуміє `NodeNext`.
- Збірка — `npm run build` (`tsc -p tsconfig.build.json`) у `dist/`: `.js`, `.d.ts` і карти. `dist/` не
  в git, у пакет іде разом із `src/` (для карт). Перевірка типів — `npm run typecheck`, разом з
  тестами.
- Публічні функції й поля — з типами в сигнатурі, `any` немає. Перевірки під час виконання для
  споживачів на чистому JS (`createClient` без `baseUrl`, `bearerToken` без `getToken`)
  лишаються: типи їх не замінюють.
- Файли: camelCase для модулів (`bearerToken.ts`), PascalCase для класів помилок (`ApiError.ts`).
- Коментарі й тексти помилок — англійською. Документація для розробників (`CLAUDE.md`, `docs/`) —
  українською, `README.md` для споживачів — англійською.
- Публічне — лише те, що експортує `src/index.ts` (і типи через `export type`). Зміна контракту з `docs/architecture.md` —
  мажорна версія і правка документа в тому самому коміті.

## Тести

```bash
npm run typecheck && npm test
```

Vitest з покриттям `@vitest/coverage-v8` (лише `devDependencies`) — та сама платформа, що й
фронт сайту. **Покриття `src/**` — 100 %**, тести — `test/**/*.test.ts` (рядки, гілки, функції, інструкції): нижче поріг —
прогін падає; `exclude` порожній, коментарі `v8 ignore` / `istanbul ignore` заборонені.

`fetch` — фальшивий, переданий у `createClient`. Тест перевіряє весь результат точним збігом:
запит, що пішов, і відповідь або помилку з усіма полями. Тест, який лише проходить рядок, не
перевіряючи поведінку, не рахується.

## Git

- **Комітити й пушити заборонено**: ні `git commit`, ні `git push`, ні команд, що комітять як
  побічний ефект (`merge`, `rebase`, `cherry-pick`, `revert`, `commit --amend`). Коміти робить
  лише людина. Робота здана, коли зміни лежать у робочому дереві, тести зелені й описано, що
  змінено.
- Повідомлення коміту для людини — англійською, тези списком.
- Зміна — у гілці з номером задачі (`SP-XXXX`) від `master`; PR у `master`
  [send-parcel/js-sdk](https://github.com/send-parcel/js-sdk) Claude готує (назва, опис тезами
  англійською, команди), створює людина. Новий метод — minor-версія в `package.json`, зміна
  контракту — major (до `1.0.0` — minor). Тег і `npm publish` — людина.
- Сайт SendParcel переходить на нову версію лише після публікації в npm; до того підключає SDK
  через `file:`, і такий `package.json` сайту не пушиться.
